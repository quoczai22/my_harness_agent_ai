# Web-Test1 3GB kit — implementation verification (2026-10-30)

Kit: `artifacts/Continuity-Web-Test1-3GB`. Change: `openspec/changes/web-test1-offline-kit-3gb`.
Nothing was committed or pushed. E: USB kits, the user's projects and SQL Server were not touched.

## What changed

- `lib/WebExam.ps1` (new): shared logic used by `Study-Exam.ps1` and tests.
  - SQL schema parser: database, tables, columns/types, NOT NULL, IDENTITY, primary keys (inline, table-level, composite, `CLUSTERED ... WITH (...)`), foreign keys (inline, `CONSTRAINT`, `ALTER TABLE ... ADD [CONSTRAINT] FOREIGN KEY`). Reads UTF-16 SSMS scripts, ignores comments and string literals in INSERT data. The prompt now carries this summary instead of a 3000-character raw excerpt, which previously cut off the FKs that SSMS writes at the end of the file.
  - Layout: extracts the shared `<header>`/`<nav>`/`<footer>` and head CSS from sample pages into a new `_Layout.cshtml` (escapes `@`, turns `*.html` links into `asp-action`, rebases assets to `~/`). Without sample pages it uses a simple Bootstrap/HTML layout. Fixed a Razor bug in the old fallback: `@media` inside `<style>` must be `@@media`.
  - Models: `Models/<Table>.cs` generated directly from the SQL (types, nullability, `Ten<Ref>` JOIN property), no AI.
  - Language: Vietnamese-only system prompt passed with `-sysf`; CJK answers are detected as drift and retried once; mojibake is reported as an encoding error, not drift.
  - `/check`: static checklist from section 17 of the authoritative spec, each item verified / failed / not tested / not required. Runtime and database behaviour is always "not tested".
  - `/build`: `dotnet build` on a throwaway temp copy (project plus drafts), NuGet restore only from the local cache, MVC5 declined.
  - Drafts: path rules, no writes outside `drafts/<session>`, no overwrite without `REPLACE`; generated `.cs` gets mechanical namespace/using repairs that are shown to the user.
- `Study-Exam.ps1`: rewritten on the library; new `/schema /check /build /drafts /help`, multiple `/view` files. Saved with a UTF-8 BOM: the previous file had none, so Windows PowerShell 5.1 decoded its Vietnamese strings as ANSI.
- `Get-Llama-Answer.ps1`: optional `-SystemFile` (backward compatible).
- `tests/Test-WebExam.ps1` and fixtures `fruit-shop`, `catalog` (now buildable), `mvc5`, `good`, `bad`.

## Evidence

- Language drift reproduced before the change: prompt `chao` with no system prompt gave Chinese 3/3. After: Vietnamese 3/3 in each of two live runs.
- Offline self-test (`Study-Exam.ps1 -SelfTest`): 71/71 passed, including a real `dotnet build` (SDK 10.0.300, net8.0) of the generated layout and models with a hand-written correct controller and views, and the check that the project folder hash is unchanged.
- Live runs (`-SelfTest -Live`, two schemas × two runs, controller + Index + Create generated by Qwen2.5-Coder-3B): reports in `tests/results/`, drafts kept in `tests/results/drafts-20261030-003201/`.
  - First run: 0/4 builds. All four failed on `using De02_Shop_Core...` copied from the reference sample.
  - After the reference-namespace fix and using-repair: 1/4 builds (fruit-shop run 2). The remaining failures are model hallucinations: invented columns (`Price`, `Quantity`, `GenreId`), Dapper `QueryAsync`, wrong `SelectList` arguments, and DELETE via GET. `/check` or `/build` flagged each one.
  - Model time on this PC: about 85–155 s for a controller and 30–45 s for a view.

## Limitations for the reviewer

- The 3B model does not reliably produce compiling controllers or views. The kit's value is the deterministic schema, layout, models and checks plus a draft to edit. It is not a one-shot solution, as the spec states.
- "Builds" does not mean "works": no app run or SQL Server test was performed.
- School hardware and a clean offline PC are untested. `/build` needs a .NET 8+ SDK and `Microsoft.Data.SqlClient` already in the NuGet cache.
- `sessions/documents`, `sessions/pdf` and `sessions/web-exams/runtime-logs` are leftovers copied from earlier kits and were left untouched.
