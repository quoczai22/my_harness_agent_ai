# Design

- Add a workspace/project-scoped string setting `continuity.assistant.checkCommand`, default empty, and `continuity.assistant.checkTimeoutSeconds`, default 120 seconds, accepted range 1–300 seconds. Empty command means `not configured`, with no check process. Support program plus arguments with quoted paths/arguments; expand `{files}` to the proposed relative file path(s) as separate arguments. Reject malformed quoting and shell operators or redirection. Run only an executable plus argument array through `execFile` with `shell: false`, the configured timeout and at most 64 KiB combined stdout/stderr. Send at most 4,000 characters of diagnostics to the model per repair round.
- Declare `capabilities.untrustedWorkspaces` in `package.json` with `supported: "limited"` and `restrictedConfigurations: ["continuity.assistant.checkCommand"]`. Check `vscode.workspace.isTrusted` immediately before any check; an untrusted workspace never copies the project or runs the command, and Composer displays a blocked/untrusted status. Before running a command string for the first time in a workspace, show a modal confirmation containing the exact configured string. Hash the command string with SHA-256 and store approved hashes in `workspaceState` scoped to the canonical workspace root. A changed string has a different hash and needs a new confirmation. Declining or dismissing keeps the command unexecuted and shows a blocked/not-approved status; approval of an earlier command never authorizes a new one.
- Integrate after `splitAssistantResponse` accepts a one-file proposal for the active editor, before `ComposerViewProvider.setProposedDiff`. Resolve the project root and target with existing workspace safety checks. Ensure the proposal's `original` is an exact unique match before using the replacement; reject mismatched/ambiguous edits rather than checking a different file from the one Composer would apply.
- Create a uniquely owned temporary directory. Copy at most 2,000 regular project files, at most 2 MiB per file and 50 MiB total; exceeding any limit fails the check clearly rather than silently testing an incomplete copy. Skip `.git`, `node_modules`, `build`, `dist` and existing sensitive/ignored paths; do not traverse symlinks or write into the source tree. Apply the proposed replacement to the temporary target. Run the configured command with `cwd` set to the temporary copy. Remove only that owned temporary directory in `finally`, including after timeout/errors/cancel. If cleanup fails, display the exact temporary path and never report `passed`. Project files are never modified by checking or repair.
- Run the check in `vscode.window.withProgress` with a Cancel button. Cancellation aborts the check, terminates the child process tree, removes the owned temporary copy and reports `cancelled`. On Windows timeout or cancellation, run fixed `taskkill /T /F /PID <childPid>` through `execFile` with `shell: false`; wait for termination before cleanup. A kill failure is reported as an error and cannot become `passed`. Ensure late model or command responses cannot publish a passed result after cancellation.
- If the command succeeds, show `passed` with the proposal. If it exits nonzero, send a bounded excerpt of diagnostics, the current proposal, and the original task/context to the configured local model. Parse only a valid revised proposal for the same target and repeat check, at most two model repair rounds. Do not invent a replacement from error text. If a repair response is invalid, report it as an unresolved check error without presenting an unverified revision as passed.
- Composer displays `passed`, `still failing after up to two repairs` with bounded diagnostics, `check command not configured`, `blocked: untrusted workspace`, `blocked: command not approved`, or `cancelled`, as applicable. Timeout/start/copy/cleanup failures are shown as check failures with a clear cause and never as passed. The user may still review or discard the proposal; only the existing explicit Apply flow may write to the project.
- Keep `sidebarViews.ts` free of runtime `vscode` imports by injecting result data. Plain-Node tests use a fake executable/model and assert immediate pass, pass after one repair, failure after two repairs, timeout, cleanup, unchanged source tree, untrusted workspace with no execution, unapproved command with no execution, and cancellation mid-check with process-tree termination. Increment the extension to 0.3.3, run `npm test`, and report what was not checked interactively.
