# Requirements

1. A per-project `continuity.assistant.checkCommand` setting SHALL default to empty. An empty setting SHALL skip execution and display `check command not configured` with the proposal. `continuity.assistant.checkTimeoutSeconds` SHALL default to 120 and accept only 1–300 seconds.
2. The extension manifest SHALL declare `capabilities.untrustedWorkspaces` with `supported: "limited"` and `restrictedConfigurations: ["continuity.assistant.checkCommand"]`. An untrusted workspace SHALL never run the check. Before first execution of each distinct command string in each workspace, a modal dialog SHALL show the exact string and require confirmation; an approved SHA-256 command hash SHALL be stored in `workspaceState` for that workspace. Changing the command SHALL require confirmation again. Rejection/dismissal SHALL prevent execution.
3. A configured and approved check SHALL run on a temporary copy containing the proposed change, never on or against the real project. The copy SHALL exclude `.git`, `node_modules`, `build`, `dist`, symlinks and sensitive/ignored files, and SHALL be limited to 2,000 files, 2 MiB per file and 50 MiB total. Exceeding a limit SHALL fail clearly, not run a partial check. The owned temporary directory SHALL be removed after every outcome; failed cleanup SHALL report its path and SHALL never report passed.
4. The command SHALL be parsed into executable and arguments, support `{files}` as separate target path arguments, and run via `execFile` without a shell, with the configured timeout and at most 64 KiB combined output. Malformed or shell-style commands SHALL fail clearly. At most 4,000 characters of diagnostics SHALL be sent to the model per repair round.
5. The check SHALL show cancellable progress. On cancellation, it SHALL stop execution, clean the temporary directory and display `cancelled`. On Windows timeout or cancellation, it SHALL terminate the full process tree with fixed `taskkill /T /F /PID <childPid>` via `execFile` without a shell, and wait for termination before cleanup. Kill or cleanup failure SHALL be reported, never passed.
6. A nonzero result SHALL feed bounded diagnostics to the local model for at most two repair rounds. Each revision SHALL target the same file and pass the normal proposal validity/safety checks before rechecking. Cancellation SHALL prevent a late result from being presented as passed.
7. Composer SHALL display the proposal with an accurate status: passed, still failing with bounded diagnostics, not configured, blocked due to untrusted workspace or unapproved command, or cancelled. Timeout/preparation/cleanup errors SHALL not be called passed. The existing user approval SHALL remain required before writing to the real project.
8. Plain-Node tests SHALL cover immediate pass, one-repair pass, failure after two repairs, timeout, temporary cleanup, no source mutation, untrusted workspace, unapproved command, and mid-check cancellation. `sidebarViews.ts` SHALL keep no runtime `vscode` import. The full extension `npm test` suite SHALL pass before implementation review.
