# Design

- Reuse `pdfText.ts` scan detection and `test-fixtures/scanned.pdf`. Preserve page numbers and extracted page text so a mixed PDF can be assembled in page order. An all-scan PDF enters the vision path instead of failing at `readAttachmentFile`. PDF limits remain 10 MB input and the first 20 pages; at most **3 scanned pages per attachment** may be transcribed. If more are detected, show a clear limit error before any transcription, with no silently omitted pages.
- The extension host reads the explicitly attached local PDF (typed `/pdf` keeps its existing project-path safety check; Attach may use the user-chosen path) and sends only its bytes and selected page numbers to the chat webview through `postMessage`. `ChatViewProvider` renders those pages on a canvas with the already bundled `dist/vendor/pdfjs` module/worker. Set the chat webview's `localResourceRoots` to **only** that vendor directory; make only its `asWebviewUri` resources loadable. Keep the CSP nonce for scripts, allow only the vendor webview origin needed by the module/worker, and keep network access disabled. Do not add a runtime `vscode` import to `sidebarViews.ts`; inject the resource URIs and callbacks from `extension.ts`.
- Rendering uses a longest edge of **1600 px**, JPEG quality **0.80**, at most **2,000,000 decoded JPEG bytes per page**, and a **90-second timeout per page** covering render and transcription. A page that cannot meet the size/time bound is marked failed; it is never silently downscaled beyond the stated dimension or sent as oversized data. Release canvas/page/document resources after each page. The webview sends bounded image data URLs back to the host; validate page number, MIME, byte length and the pending request identity before any model call.
- Vision eligibility is checked before rendering/model requests: selected provider must be LM Studio and its configured model must be reported as `type: "vlm"` and loaded by local `/api/v0/models` (with a compatible local capability check where required by the current client). An Ollama or non-VLM selection shows a clear message pointing to **Assistant: Select Local Provider and Model**; the extension never silently changes provider/model or loads/downloads one. If the required model metadata is unavailable, fail closed with an explicit message.
- For each accepted page image, call LM Studio locally with a transcription-only prompt: copy the page verbatim, preserve Vietnamese diacritics, do not solve the exam and do not add code or inferred text. Send `reasoning_effort: "none"` only if required/supported by the local endpoint. A blank response, timeout or model/render error becomes `[Trang N: không đọc được — lý do]` in the review text, not invented exam content. Bound each page transcript to **10,000 characters** and the combined exam context to the existing **40,000-character** PDF budget.
- Show cancellable VS Code progress during render/transcription. Link Cancel to an `AbortController` for in-flight local API requests and a webview cancel message for rendering. Do not continue to later pages after cancellation. The editable transcript review in chat has **Xác nhận** and **Hủy** buttons; only after Xác nhận assemble extracted text and edited scan transcript with page markers and send the user's original question plus that text to the model. Hủy or progress cancellation sends nothing, creates no assistant answer, and does not persist unconfirmed transcription or image data in session history. Ensure a late response from an older/cancelled request cannot be confirmed or sent.
- Put sequencing, bounds, eligibility and confirmation state in plain TypeScript with injected renderer/model functions so `npm test` can run under Node without VS Code. Cover the existing scanned PDF fixture, successful transcription then edited confirmation, review cancellation, unsupported provider/model, page/size/time limits, empty model response, and in-flight cancellation. Test CSP/resource-root generation separately. Increase version to 0.3.4; run full extension tests, package and install the local VSIX, verify installed version, and report any webview/real-model behavior not exercised.
