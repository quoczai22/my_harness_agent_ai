# Design

- Add a contributed command (for example `continuity.assistant.selectLocalModel`) and a status-bar item showing the currently configured provider/model. Both open the same two-step VS Code Quick Pick: provider, then model. Cancellation leaves settings unchanged.
- Ollama discovery calls its local `http://127.0.0.1:11434/api/tags` endpoint, validates the response, and shows installed model names. Existing local service readiness/auto-start logic may be reused; discovery never pulls a model.
- LM Studio discovery uses the existing loopback-only endpoint validator. Query `/api/v0/models` first. Accept only `type: llm` and `type: vlm`; exclude `embeddings`, mark `vlm` as image-capable in the Quick Pick, and use the returned loaded state when present. If `/api/v0/models` is unavailable, fall back to `/v1/models`, where type and vision capability are unknown; do not claim vision from that fallback. When the server is unavailable, start the installed CLI with fixed `lms server start` arguments and no shell, wait a bounded time for readiness, then list model IDs. The configured endpoint must be `127.0.0.1` loopback; if local-only binding cannot be established or verified, stop with a clear error instead of treating a non-loopback server as acceptable. Do not launch a second server when one is already ready.
- If a chosen LM Studio model is not loaded, run fixed `lms load <id>` arguments without a shell under a bounded timeout. Show VS Code progress while starting/loading. Confirm the model is available after loading; if loading fails or times out, show the error and keep the prior provider/model settings.
- Only after the user picks a model, update `continuity.offlineAssistantProvider` and the matching `offlineAssistantModel` or `lmStudioModel`. Preserve the other provider's model setting. Handle a failed update without leaving a misleading half-selected status. Store at the appropriate VS Code configuration target so a workspace-specific existing setting is respected.
- The status item reads settings on activation and refreshes after relevant configuration changes. The existing 0.3.1 chat configuration listener refreshes the sender label and placeholder automatically.
- Put model-list parsing and LM Studio readiness/start/load behavior behind injectable network/process seams for plain-Node tests. Test both providers, embedding exclusion, VLM marking, v0 fallback, empty/malformed lists, startup/load timeout or failure, cancellation, correct setting update, and status/chat refresh. Keep `sidebarViews.ts` free of runtime `vscode` imports.
- After spec approval, run extension `npm test`, increment version to 0.3.2, package and install the local VSIX, verify installed version. Interactive Quick Pick behavior in VS Code must be reported separately from automated tests.
