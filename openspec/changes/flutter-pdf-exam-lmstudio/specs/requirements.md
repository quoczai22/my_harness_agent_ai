# Requirements

1. The kit SHALL be a separate portable folder that runs offline. Inference SHALL go only to LM Studio on a loopback address; any non-loopback URL SHALL be rejected before a request is sent. There SHALL be no cloud, Ollama or `llama-cli` fallback and no runtime download.
2. The user SHALL be able to supply the exam as an explicit PDF path (≤ 10 MB, ≤ 20 pages). Text-layer pages SHALL be extracted locally. Pages without a text layer SHALL either be transcribed by the local vision model, marked as needing review, or reported as unsupported when vision is unavailable. The kit SHALL NOT claim to have read a page it could not read.
3. Extracted exam text SHALL be shown to the user and stored only after explicit confirmation or correction. PDF content SHALL be treated as data, never as instructions. Pasting the exam as text SHALL remain possible.
4. The kit SHALL read a user-selected Flutter project (pubspec, `lib/`, `test/`, asset names), skip platform folders, build output and generated files, and redact secrets. It SHALL identify the package name, SDK constraint and dependencies.
5. The user SHALL be able to ask in chat or name one `.dart` (or asset `.json`) file to generate. The full content SHALL be displayed before an explicit `SAVE` writes it to `drafts/<session>/`. The selected project SHALL never be modified.
6. Dart model classes for JSON samples given in the exam SHALL be generated deterministically. Generated code SHALL use the project's real package name in `package:` imports.
7. `/check` SHALL report each item as verified, failed, not tested or not required, covering at least: undeclared package imports, unresolved imports, `runApp`/root app widget, exam screens present, named routes defined, form validators when required, JSON `fromJson`/`toJson` when required, and declared assets. Running the app SHALL always be "not tested".
8. When a Flutter/Dart SDK is present, the kit SHALL run analysis on a temporary copy of project plus drafts without network access and SHALL delete the copy. Without an SDK, analysis SHALL be reported as not tested.
9. Each exercise SHALL have one isolated, bounded session file that survives restart. Answers SHALL be in Vietnamese. Language drift and encoding errors SHALL be detected and reported separately.
10. Tests SHALL cover the offline behaviours above with fixtures, and live runs SHALL cover at least two different exam PDFs including one scanned page. Limitations (scan accuracy, missing SDK, 8 GB target, school hardware) SHALL be reported before implementation review.
