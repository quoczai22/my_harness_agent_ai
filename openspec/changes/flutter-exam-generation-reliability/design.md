# Design

Before showing a generated file, inspect it against the confirmed exam requirements and the analyzer result. When validation is required, detect bare `TextField` use in the proposed screen and perform a targeted repair pass requiring `Form`, `GlobalKey<FormState>`, `TextFormField`, field-specific validators and a `validate()` gate. Reanalyze the repaired file. If the structure still fails, report the exact missing elements. The kit never saves automatically or claims the file passed; the user may still choose SAVE after seeing the warning.

Treat output truncation as a kit-level failure mode. The latest `run2-product_app/lib/screens/add_product_screen.dart` draft starts with an unmatched opening ` ```dart ` fence and ends with the chat warning `[Bị cắt do giới hạn độ dài; hỏi tiếp phần còn lại.]`; the resulting file produced 29 analyzer errors. Preserve `finish_reason=length` as structured response metadata for code generation instead of appending a conversational warning to source text. `Remove-CodeFence` must remove an opening fence even when no closing fence arrived, and warning text must never enter a draft or repair prompt as Dart code. Detect incomplete output from `finish_reason=length` or a bounded structural check such as unbalanced braces. Attempt a bounded continuation only if it can be joined unambiguously and revalidated; otherwise show a clear incomplete-file warning and leave SAVE under the user's control. Do not pass a known incomplete file to analyzer or model repair as though it were complete. Add a regression fixture for the unmatched fence and truncation warning.

For `undefined_identifier` and `undefined_getter`, collect the exact analyzer symbol, source line and real declarations in the relevant `State` class or existing model. Supply these facts to a bounded repair pass. Mechanical replacement is allowed only when a unique, type-compatible existing name can be demonstrated; otherwise show the unresolved error. Never invent a field from a guessed exam interpretation. Add regression fixtures for a missing `notes` field, `_formState`, and incorrect access to fields of `Map<String, Object?>` or `FormState`.

The existing two-round model repair ceiling, draft-before-save gate, offline SDK analysis and Vietnamese user messages remain. Because Qwen3.5-2B output varied strongly across runs, run at least three repetitions per exam for both baseline and changed kit, using the same fixtures, model, context and generation settings. Record each run and the min–max range of file and whole-project clean-compilation rates before and after; report checklist outcome and remaining errors separately. A single-run difference is not evidence of improvement.
